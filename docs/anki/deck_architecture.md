# 软考 Anki 卡组架构

## 目标

软考 Anki 资产采用“双轨制卡”：

1. 章节概念卡：按章节整理稳定概念、文档、过程、角色、输出物、方法和规则。
2. 专题问答卡：按专题整理考试判断、辨析、流程、案例、陷阱和真题反哺。

两类卡可以合理冗余，但必须能分开复习。

## 推荐物理卡组

```text
软考::系统集成项目管理工程师
  章节概念卡
    01_信息化与信息系统
    02_项目管理基础
    03_立项管理
    ...
  专题问答卡
    01_信息化与信息系统
      T-INFO-001_...
    02_项目管理基础
      T-PM-002_...
    ...
  计算专题卡
    T-COST-002_挣值管理
    T-SCH-003_关键路径
    T-COM-001_沟通渠道
    T-RISK-002_EMV与决策树
  真题刷题卡
    上午选择题
    下午案例题
  跨专题辨析
  待核验与复查
```

当前样例和 full build 也允许使用章节下双轨路径：

```text
软考::系统集成项目管理工程师::03_立项管理::章节概念卡::03_立项管理_概念卡
软考::系统集成项目管理工程师::03_立项管理::专题问答卡::T-FEA-001_...
```

关键要求不是唯一目录形式，而是章节概念卡、专题问答卡、计算专题卡、真题卡和待核验卡必须能分开筛选和复习。

## 为什么按章节建概念卡

章节概念卡像“章节内术语词典”，解决的是“这个章节有哪些对象必须稳定识别”。它适合新学章节、查漏补缺和考前扫盲。

## 为什么按专题建问答卡

专题问答卡更接近考试反应训练，解决的是“题干出现某种场景时如何判断”。它适合刷选择题、案例题、易混点和陷阱。

## 标签体系

基础标签：

```text
ruankao
ruankao::manual_sample
ruankao::chapter::03
ruankao::domain::立项管理
```

章节概念卡：

```text
ruankao::family::chapter_concept
ruankao::concept::<概念名>
```

专题问答卡：

```text
ruankao::family::topic_qa
ruankao::topic::T-FEA-001
```

待核验：

```text
ruankao::needs_review
ruankao::not_for_main_review
```

## 导入原则

- 用户确认样例风格前，不进行全量导入。
- 导入前必须检查字段、checksum、deck 路径、needs_human_review 隔离。
- 不使用代码质量评分工具判断卡片质量。
- 卡片质量由制卡者逐张自然语言自评，再交给用户抽样验收。
