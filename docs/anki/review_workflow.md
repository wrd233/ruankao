# Anki 卡片人工审稿流程

## 审稿问题

每张卡至少回答：

1. Front 是否让人明确知道要回忆什么？
2. Back 是否是最小稳定答案？
3. 这张卡是否只考一个点？
4. Extra 是否是本卡专属，而不是通用套话？
5. 这张卡是否能帮助上午选择、下午案例、跨域辨析或题干识别？
6. 有没有把标题、导语、来源摘抄或制卡说明伪装成卡片？
7. 有没有和其他卡同义重复？
8. 是否需要标记 `needs_human_review`？

## 状态定义

- `keep`：可以进入样例审稿包。
- `revise`：方向正确，但 Front/Back/Extra 仍需改写。
- `needs_human_review`：来源冲突、法规数字、OCR 疑点或教材版本疑点，不进入主复习。
- `reject`：不应进入本轮卡片资产。

## 常见拒绝原因

- Front 过大，如“某专题的考试要点是什么”。
- Back 是长段摘抄。
- Extra 只是“抓住题干中的对象、动作和输出”一类通用句。
- 来源不稳却写成确定答案。
- 和另一张卡答案几乎相同。
- 真题题干、答案和解析边界不稳定。

## 待核验处理

涉及法规数字、标准编号、教材版本差异、OCR 疑点时：

```text
manual_review_status = needs_human_review
tags += ruankao::needs_review ruankao::not_for_main_review
```

Back 可以写稳定方向，但不能要求用户强背不确定数字。

## 导入前门禁

用户确认样例风格前，不做全量生成，不导入 Anki。

样例通过后，才允许按章节逐步扩展。扩展时仍然先做人类可读样例包，再考虑导入。
