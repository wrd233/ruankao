# 章节概念卡规范

## 定义

章节概念卡用于复习一个章节内必须稳定掌握的概念、文档、过程、角色、输出物、方法、指标和规则。它不是专题摘要，也不是教材提纲。

## 可进入章节概念卡的内容

- 名词术语：项目建议书、可行性研究、项目评估。
- 文档/产物：需求分析报告、可研报告、项目章程、投资概算。
- 过程/阶段：机会研究、初步可研、详细可研、项目审批。
- 角色/组织：项目审批部门、咨询评估机构、项目发起人。
- 评价维度：技术可行性、财务可行性、组织可行性、社会可行性。
- 规则性判断：重大变更重新报批、法规数字待核验。
- 易混边界：项目建议书 vs 项目章程，项目论证 vs 项目评估。

## 不进入章节概念卡的内容

- 小节标题本身。
- “先看这个专题的主线”。
- “本轮真题覆盖增强”。
- “典型题详解与举一反三”。
- 制卡过程说明。
- 只有资料组织价值、没有复习价值的句子。

## Front 写法

优先使用具体问题：

```text
X 是什么？
X 的核心作用是什么？
X 通常出现在项目的哪个阶段？
X 主要服务于什么决策？
X 与 Y 的核心区别是什么？
题干出现哪些信号时，应想到 X？
X 不等于什么？
X 的输出或依据是什么？
```

避免：

```text
某章节的考试要点是什么？
某标题的考试判断要点是什么？
这个专题应该怎样转化为 Anki 卡片？
```

## Back 写法

Back 一般 1 句话，最多 2 句话。它必须是最小稳定答案。

好例：

```text
项目建议书是立项前提出拟建项目总体设想和立项申请的文件，为项目选择和后续可行性研究提供依据。
```

坏例：

```text
项目建议书是立项管理中的核心材料，本节主要介绍它的定义、内容、审批、和可行性研究的关系……
```

## Extra 写法

Extra 只放帮助复习的内容：

```html
<div>理解：...</div>
<div>记忆线索：...</div>
<div>易错点：...</div>
<div>题干信号：...</div>
<div>关联：...</div>
<div>来源：tutorial 5.1.1。</div>
```

不放大段来源原文，不写通用套话。

## 人工审稿

每张卡必须填写：

```text
manual_review_status = keep / revise / needs_human_review / reject
manual_review_note = 一句话自然语言理由
```

禁止使用代码质量评分工具评价卡片质量。禁止输出 `quality_score` 字段。
