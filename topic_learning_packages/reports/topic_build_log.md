# 专题建设日志

> 记录专题拆分、合并、重命名和调整理由。

## 结构调整记录

### 调整 001：进度管理专题合并
- **原专题**：topic_build_full 中 T-SCH-004（活动历时估算、PERT）和 T-SCH-005（进度压缩、赶工、快速跟进）
- **新专题**：T007 样例已将 PERT + 进度压缩合并为一个专题
- **调整类型**：合并
- **原因**：真题中 PERT 和进度压缩常共同出现，单独讲估算无法形成完整题型闭环
- **影响**：T007 样例已经覆盖了旧 T-SCH-004 + T-SCH-005 的内容

### 调整 002：专题 ID 体系建立
- **原专题 ID**：topic_build_full 使用 XX-NN 格式（如 06-05），outputs/02 使用 T-XXX-NNN 格式（如 T-SCH-004）
- **新专题 ID**：本轮使用 T-XXX-NNN 格式
- **调整类型**：标准化
- **原因**：统一 ID 体系，便于在 manifest、覆盖矩阵和制卡工具间互通
- **影响**：在 topic_manifest.json 中维护映射表

### 调整 003：综合辨析专题设立
- **原结构**：topic_build_full 中 18_真题高频与易错专题 包含多个独立辨析文件
- **新结构**：在 99_综合专题与跨域辨析 下建立 T-CROSS-001，集中覆盖 9 对高频辨析
- **调整类型**：合并重组
- **原因**：高频辨析题各对概念有相似的出题模式，集中在一篇讲义中更方便学习者建立"辨析框架"
- **影响**：后续可按需拆分，但不影响当前学习体验

### 调整 004：案例专题与知识域专题的关系
- **策略**：T-CASE-001（通用方法）与各知识域专题中的案例题不重复，而是互补
- **分工**：T-CASE-001 讲"怎么答题"，知识域专题中的案例题讲"这个领域的案例怎么诊断"
- **调整类型**：分层设计
- **原因**：避免每个案例专题都重复讲审题方法

### 调整 005：目录结构从 topic_build_full 迁移至 topic_learning_packages
- **原目录**：topic_build_full/topics（含 95 个骨架文件和 18 个子目录）
- **新目录**：topic_learning_packages/topics（含 16 个知识域目录 + 11 个正式专题）
- **调整类型**：重构
- **原因**：新的目录结构更贴合建设说明 v2 的推荐结构，且明确区分了骨架（C/D 级）与正式专题（A 级）
- **影响**：topic_build_full 保留作为历史参考和素材来源
