# 04｜真题考法与题目映射索引

> 本表以专题为单位聚合题型，不逐题复制所有题干；代表性题来自 DocMind `questions.full.clean.md`、2020 选择题、2020 上午题、系统集成试题库和总结经典案例。

| 专题 | 选择题考法 | 计算题/案例题考法 | 常见陷阱 |
|---|---|---|---|
| `00-01` 考试结构、上午题与下午案例题能力差异 | 问能力差异、答题方式、案例失分点 | 看到需求未确认且进度延期的案例，先定位范围、进度、沟通、变更四类证据 | 上午题不是案例发挥题 |
| `00-02` 软考专题到 Anki 的转化原则 | 常问如何从专题生成原子卡 | 范围确认 vs 控制质量应先做一张对比卡，再拆正式验收和质量检查两张判断卡 | 可引用不等于可制卡 |
| `01-01` 信息、信息化与国家信息化体系 | 常考国家信息化体系要素、信息质量属性、两化融合 | 题干问体系要素时，不要把某个企业应用系统当成国家层面要素 | 信息系统 vs 信息化 |
| `01-02` 企业应用系统：ERP、CRM、SCM、EAI、BI | 历年题常考 ERP 最大特点、CRM 数据、BI/ETL/OLAP、EAI 集成层次 | 题干说把客户需求、企业制造和供应商资源整合起来，通常考 ERP 向供应链扩展 | ERP vs SCM |
| `01-03` 信息系统生命周期与系统集成项目特点 | 常考生命周期阶段、典型信息系统开发过程、系统集成项目特点 | 项目交付后进入长期维护，说明建设项目结束但信息系统生命周期继续 | 项目生命周期 vs 产品生命周期 |
| `01-04` 软件工程方法、过程模型与测试基础 | 常考结构化/原型/面向对象适用场景、测试类型和阶段 | 需求难以一次说清时，用原型帮助澄清需求，而不是直接进入详细设计 | 原型不是最终系统一次具备全部性能 |
| `01-05` 需求工程与需求跟踪 | 下午范围案例常从需求误解、翻译传递、未签字确认出题 | 视频聊天被客户理解为电子商务核心功能，根因是需求获取和范围确认不足 | 需求不清 vs 范围蔓延 |
| `01-06` 系统架构、UML 与应用集成技术 | 常考 UML 视图、Web Service 三角色、EAI 层次 | 题干说用于装配与发布物理系统的构件和文件，常指 UML 实现视图 | 架构设计 vs 详细编码 |
| `01-07` 网络、综合布线、信息安全与新技术趋势 | 题库出现 AP、SAN、综合布线、云计算服务类型、大数据关键技术 | 题干说块级数据访问、高扩展共享存储，通常定位 SAN | 安全管理不等于只上防火墙 |
| `02-01` 项目特性、项目目标与多目标权衡 | 常考项目特点、目标特性、三重制约和案例权衡 | 客户要求提前上线时，要同时评估范围、成本、质量和风险，不能只要求团队加班 | 项目 vs 运营 |
| `02-02` 项目生命周期、阶段门与产品生命周期 | 常考项目生命周期是产品生命周期的一部分、阶段审查目的 | ERP 建设项目结束后系统进入运维，说明产品或系统生命周期仍在继续 | 阶段不是过程组 |
| `02-03` 五大过程组、十大知识领域与 PDCA | 常考 PDCA 对应、过程组归属、创建 WBS 属于规划过程组 | 创建 WBS 同时属于范围管理知识领域和规划过程组 | 过程组 vs 项目阶段 |
| `02-04` 组织结构与项目经理权限 | 常考 PM 权限、资源可用性、沟通复杂度 | 成员同时向职能经理和项目经理汇报，通常是矩阵型，再看权力强弱 | 矩阵型不等于 PM 一定强 |
| `02-05` 项目经理职责、能力与软技能 | 下午题常问项目经理不妥之处和应采取措施 | 项目经理兼任配置管理员并忽略版本控制，既是角色冲突也是配置管理问题 | 领导 vs 管理 |
| `02-06` PMO、项目集与项目组合管理 | 常考 PMO 职责、项目集与项目组合区别 | PMO 统一方法并审查里程碑，可能是控制型；直接分派项目经理则更接近指令型 | PMO 不是一定不能决策 |
| `03-01` 项目建议书与立项审批逻辑 | 常考建议书内容、重大变更重新报批、审批逻辑 | 可研报告内容较建议书批复有重大调整时，应考虑重新报批 | 项目建议书 vs 可研报告 |
| `03-02` 可行性研究内容与七步法 | 常考可研内容、七步顺序、可研方法 | 采用新技术但团队无经验且用户数据不足，是技术和运行环境可行性不足 | 运行环境可行性容易被忽视 |
| `03-03` 机会研究、初步可研与详细可研 | 常考精度、目的和阶段排序 | 多方案中选择最优并进行详细技术经济论证，定位详细可行性研究 | 初步可研不是最终报告 |
| `03-04` 项目论证与项目评估 | 常考主体、立足点、先后关系 | 由第三方根据可研报告和资源协议审查，更接近项目评估 | 论证不是简单写报告 |
| `03-05` 投资估算与经济评价基础 | 历年题考静态和动态投资回收期、贴现率 | 第2年末仍差100万，第三年贴现收益900万，则动态回收期可写为3-1+100/900 | NPV vs 投资回收期 |
| `04-01` 整体管理主线：章程、计划、执行、监控、变更、收尾 | 常考过程输出、整体计划缺失、变更未纳入整体控制 | 各小组各自执行子计划且原则上不允许修改，常见问题是缺乏整体管理和变更机制 | 整体管理不是替代其他知识领域 |
| `04-02` 制定项目章程与项目经理授权 | 常考谁发布章程、章程作用和内容 | 公司发布章程后指定小张为项目经理，说明章程完成授权作用 | 项目章程 vs 项目管理计划 |
| `04-03` 制定项目管理计划与基准体系 | 常考经干系人同意的项目管理计划是项目基准 | 项目目标、可交付成果、边界和质量指标更像范围说明书；整合各分计划才是项目管理计划 | 项目管理计划 vs 章程 |
| `04-04` 指导与管理项目工作 | 常考指导与管理项目工作的输出 | 团队完成模块并记录完成百分比和实际成本，这些原始记录属于工作绩效数据 | 可交付成果 vs 核实的可交付成果 vs 验收的可交付成果 |
| `04-05` 监控项目工作与工作绩效报告 | 常考项目周报、绩效分析图表、状态报告归属 | 本周完成40%是数据，进度落后10%是信息，月度状态报告是报告 | 报告不是任意表格 |
| `04-06` 实施整体变更控制与 CCB | 常考第一步写书面变更请求、批准后 PM 行动、小项目变更口头确认错误 | 需求基线已确定后客户新增功能，不能直接开工，应记录、分析、审批、沟通 | 客户至上不等于客户一提就改 |
| `05-01` 范围管理闭环：需求、范围、WBS、验收、控制 | 常考范围基准组成、确认范围含义、范围蔓延案例 | 客户后期说核心功能其实是网上交易，应回到需求和范围说明书确认问题 | 产品范围 vs 项目范围 |
| `05-02` 规划范围管理与需求管理计划 | 常考计划文件和内容文件混淆 | 没有规定成果如何正式验收，后期客户不签字时会暴露范围管理计划缺陷 | 范围管理计划 vs 范围说明书 |
| `05-03` 收集需求与需求跟踪矩阵 | 常考收集需求输出和工具 | 需求跟踪矩阵可把客户要求追踪到设计模块、测试用例和验收项 | 原型是收集需求工具 |
| `05-04` 定义范围与项目范围说明书 | 常考由目标、可交付成果、边界、质量指标识别范围说明书 | 合同写按通常行业标准提供技术支持过于模糊，应具体化范围和响应标准 | 范围说明书 vs 合同附件 |
| `05-05` 创建 WBS、WBS 字典与范围基准 | 常考 WBS 最底层不是功能模块、范围基准组成 | 把大型列表 WBS 改成树形，要说明树形直观但大型项目不易修改和装订 | WBS vs 活动清单 |
| `05-06` 确认范围、控制质量与控制范围 | 历年题直接考范围确认正确描述 | 测试通过是核实的可交付成果，客户签字后才是验收的可交付成果 | 确认范围不是质量控制 |
| `06-01` 进度管理总览：从活动到进度基准 | 常考各过程输出和进度失控原因 | 重新制定4个月计划却盲目增派新人，问题可能是估算、评审和资源能力不足 | 活动清单不是 WBS |
| `06-02` 活动排序、依赖关系、PDM/AOA 与提前滞后量 | 2020 题考编码前不能测试是强制依赖 | 测试必须等编码产物完成是强制依赖；经验习惯形成的顺序可能是选择性依赖 | 先后发生不一定是强制依赖 |
| `06-03` 关键路径、总时差与自由时差 | 历年题考关键路径法错误说法、关键路径变化 | 若 B 拖延4天后 ABEH 超过 ACEH，则关键路径发生变化 | 关键路径不一定包括所有控制点 |
| `06-04` 活动资源估算、资源日历与资源优化 | 常考活动资源估算输出和资源平衡影响 | 盲目增派新人赶工可能因学习曲线和沟通成本导致效率下降 | 资源数量不等于生产率 |
| `06-05` 活动持续时间估算、三点估算与 PERT | 2020 题考活动历时等于工作数量除以生产率、PERT 三点估算 | O=4、M=7、P=16，则期望时间为8 | 三点估算不是只估一次 |
| `06-06` 进度压缩、赶工、快速跟进与控制进度 | 2020 Q1/Q2/Q8 考快速跟进、关键路径赶工、压缩代价 | 需求调研和方案设计重叠是快速跟进，但需求未确认会增加返工和变更风险 | 快速跟进不是减少任务 |
| `07-01` 成本管理总览、成本类型与成本基准 | 历年题考间接成本、成本超支和成本控制工作 | 企业统一培训费中部分计入 A 项目，若非 A 项目单独发生通常属间接成本 | 培训费用分摊可能是间接成本 |
| `07-02` 成本估算方法与储备分析 | 常考自下而上估算第一步、储备区别 | 采用自下而上估算时，先识别并估算每个工作包或最详细活动的成本 | 应急储备用于已知未知，在成本基准内 |
| `07-03` 成本预算、成本基准与资金限制平衡 | 常考成本预算输出和基准概念 | 挣值计算通常使用绩效测量基准，不把管理储备混入 BAC | BAC 不含管理储备 |
| `07-04` 挣值管理：PV、EV、AC、CV、SV | 下午题多次要求计算 CV、SV 并判断状态 | PV=177000、EV=137000、AC=179600，则 CV=-42600 成本超支，SV=-40000 进度落后 | EV 不是实际成本 |
| `07-05` CPI、SPI、EAC、ETC、VAC 与成本控制 | 历年题给 BAC、EV、AC 要求 ETC/EAC | 若 CPI<1 且 SPI<1，应判断成本超支、进度落后并提出纠偏 | CPI=0.91 不是投资91创造100 |
| `08-01` 质量管理总览：质量、等级、过程与责任 | 常考质量和等级、六西格玛、TQM、质量职责 | 低价打印机等级低但符合规格就是质量合格，高端服务器频繁宕机就是质量不合格 | 质量 vs 等级 |
| `08-02` 规划质量管理与质量成本 | 案例中质量计划随意编制、未评审常为不妥点 | 需求分析说明书未经内部评审就进入下一阶段，是质量计划执行和评审控制缺失 | 质量测量指标不是口号 |
| `08-03` 实施质量保证、质量审计与过程分析 | 下午质量案例常问 QA 工作和不妥之处 | 程序员兼任质量保证人员，可能缺少独立性、经验和权威 | QA 针对过程，QC 针对结果 |
| `08-04` 控制质量与七种基本质量工具 | 常考排列图、控制图、质量控制输入输出 | 大量缺陷集中少数模块，先用帕累托定位主要问题，再用因果图分析根因 | 帕累托抓主要少数，因果图找根因，控制图看受控 |
| `09-01` 人力资源管理计划、RAM、OBS 与 RBS | 常考人力资源计划输出和责任分配矩阵 | 一个工作包无人负责或多人都以为别人负责，应补 RAM 而非只口头说明 | RAM 不是组织结构图 |
| `09-02` 组建、建设与管理项目团队 | 常考团队建设工具和团队阶段 | 临时增派新人赶工，要安排培训、导师、评审和沟通机制 | 组建团队不是团队建设 |
| `09-03` 冲突管理与激励理论 | 常考冲突方式和激励理论 | 核心成员争论技术方案，项目经理宜组织事实分析和共同解决，而非简单命令一方 | 妥协不是双赢 |
| `09-04` 沟通模型、沟通方式与沟通管理计划 | 案例常考取消例会、客户长期不接触、销售单方通知 | 取消每日例会可能节省时间，但需求和设计并行时会放大信息不同步风险 | 沟通不等于报告 |
| `09-05` 沟通渠道计算与会议管理 | 沟通渠道数是固定高频计算题 | 10 人沟通渠道为45，新增2人后变66，协调成本显著增加 | 沟通渠道不是实际每天消息数 |
| `10-01` 干系人识别、登记册与分析矩阵 | 常考登记册、矩阵和关键干系人遗漏 | S 主管长期未参与，导致项目组误把翻译沟通当成充分确认 | 客户代表不一定代表所有用户 |
| `10-02` 干系人参与度评估与管理策略 | 案例常考客户不满、用户抵制、部门冲突 | 建设方新需求被销售直接拒绝，应通过协商、影响分析和问题日志管理 | 参与不足不只是沟通次数少 |
| `10-03` 沟通与干系人冲突类案例模板 | 下午题常给客户长期不参与、销售单方沟通、无签字确认 | 加强沟通应展开为识别关键干系人、定期评审、书面确认、纪要跟踪 | 沟通问题和范围问题常伴生 |
| `11-01` 风险管理总览与风险登记册 | 常考风险流程顺序和风险登记册 | 新人生产率低是问题，若继续增派新人可能导致质量下降才是风险 | 风险是未发生不确定性，问题是已发生事项 |
| `11-02` 风险识别工具与风险分解结构 | 常考德尔菲用途、风险识别工具 | 采用新框架但团队无经验，可登记新技术学习曲线导致进度延误 | 德尔菲强调匿名多轮反馈 |
| `11-03` 定性风险分析与概率影响矩阵 | 常考通过概率和影响评估风险优先级就是定性分析 | 中概率但会合同违约的风险，优先级可能高于小概率小影响风险 | 定性不是拍脑袋 |
| `11-04` 定量风险分析、EMV 与决策树 | 常考定量风险技术、EMV 和决策树 | 方案A 40%收益100万、60%损失20万，EMV 为28万 | EMV 不是最可能结果 |
| `11-05` 风险应对策略、储备与控制风险 | 常考规避、转移、减轻、接受场景 | 对缺乏经验的模块可培训和原型验证减轻，也可外包转移部分风险 | 转移不消除风险 |
| `12-01` 采购管理总览与自制外购分析 | 常考采购过程和自制外购分析 | 中心机房电力改造分包给专业单位，仍需合同、质量和进度控制 | 采购文件由买方准备，建议书由卖方准备 |
| `12-02` 采购工作说明书、采购文件与供方选择 | 常考买方建议书根据采购文件制定、加权评分 | 技术能力权重20%，平均8分，单项综合分可为1.6 | 采购 SOW 不同于项目章程 SOW |
| `12-03` 合同类型与风险分配 | 历年题问卖方避免成本超支应选择总价合同 | 需求明确且买方希望控制总价，可采用固定总价；需求不确定则易产生变更争议 | 总价合同对卖方风险高 |
| `12-04` 合同内容、变更、索赔与合同收尾 | 2019 下午合同案例考分包、补充协议、索赔流程 | 软件交付后买方应尽快付款缺少明确时间，应修改合同条款 | 合同变更不是普通项目变更 |
| `12-05` 招投标、政府采购与供方选择法规基础 | 2020 上午题考单一来源条件和公开招标定义 | 原合同120万追加15万超过10%，可能不满足配套添购条件 | 公开招标不是邀请一定范围 |
| `13-01` 信息文档管理与项目文档体系 | 案例常考无签字、无纪要、无归档 | 客户会议确认需求变更但未形成纪要签字，后期争议缺少证据 | 会议纪要可作为管理记录但不等于所有工作记录都是配置项 |
| `13-02` 配置项、配置基线与配置库 | 常考三类基线、配置库权限 | 源代码 Xv1.0 纳入基线后，开发人员不能直接修改发布 | 开发库可频繁修改，受控库不能随便改 |
| `13-03` 配置控制、状态报告与配置审计 | 案例常问正常配置管理工作包括哪些活动 | 程序文件规定基线变更申请评估实施后便可发布，缺少验证确认 | 状态报告不是绩效报告 |
| `13-04` 项目变更管理原则、角色与流程 | 常考变更流程步骤和角色职责 | 领导口头要求调整方案时，项目经理应记录请求、分析影响、提交 CCB | 项目经理组织控制变更，不是个人批准所有变更 |
| `13-05` 配置管理与变更管理辨析 | 历年题考 CCB/CMO 职责错误、版本直接发布 | 开发人员把 V1.4 直接发布，违反配置库权限和变更验证发布流程 | 配置管理员不是 CCB |
| `14-01` 知识产权：著作权、专利权与商标权 | 常考著作权特性、职务作品、软件著作权 | 委托开发系统未约定源代码和著作权归属，后续维护升级可能争议 | 著作权不保护思想本身 |
| `14-02` 合同法律基础与有效合同原则 | 常考合同主要内容、法律特征和有效原则 | 按通常行业标准提供技术支持过于模糊，应明确服务范围和标准 | 合同不是一方宣布就无效 |
| `14-03` 信息安全、保密与网络安全基础 | 常考 CIA 属性、机房安全、访问控制 | 数据库被未授权修改主要破坏完整性，系统宕机主要影响可用性 | 保密性不是唯一目标 |
| `14-04` 系统集成资质、监理资质与版本风险 | 2020 上午题和历年题考系统集成资质条件 | 旧题按旧资质条件考一级资质，应按题干时代和给定资料判断 | 企业资质 vs 个人项目经理资质 |
| `15-01` 招标方式与招投标程序 | 2020 上午题考公开招标定义错误项 | 以公告方式邀请一定范围法人是错误表述，公开招标面向不特定投标人 | 公开招标不是邀请一定范围 |
| `15-02` 政府采购方式与单一来源条件 | 2020 上午题以120万原采购、追加15万考比例 | 120万追加15万超过10%，通常不满足配套添购条件 | 紧急必须不可预见 |
| `15-03` 投标文件、售前交流与供应商项目立项 | 教程第5章覆盖承建方投标和供应商立项 | 售前承诺后续都支持若未写入合同，会形成范围和合同风险 | 客户需求交流不是需求基线 |
| `15-04` 开标评标中标与否决投标陷阱 | 招投标题常以应当、可以、不得设陷阱 | 投标文件未按要求签署或密封，即使技术方案优秀也可能被否决 | 最低价不一定中标 |
| `16-01` 关键路径与浮动时间计算模板 | 下午题常给活动表求网络图和关键路径 | 活动有多个紧前时，最早开始取所有紧前最早完成的最大值 | 日历日期和相对天数统一口径 |

| `16-04` 沟通渠道、EMV 与经济评价计算 | 历年题考沟通渠道、EMV、静态动态回收期 | 10 人沟通渠道为45，方案 EMV 为正不代表必然盈利 | 沟通渠道不是 n 的平方 |

| `17-01` 案例题通用阅读法与答题组织 | 总结经典强调下午题偏原因题和方法题 | 问不妥之处时逐句检查未计划、未评审、未确认、未走变更、角色不独立、沟通不闭环 | 不要复述背景 |
| `17-02` 范围失控类案例模板 | 2019 下午范围案例考范围说明书和变更控制 | S 主管要求新增电子商务核心功能，应先确认范围偏差并走变更控制 | 范围蔓延不是所有变更 |
| `17-03` 进度延误类案例模板 | 历年案例中增派新人、取消例会、需求设计重叠是典型证据 | 延期项目先用关键路径定位瓶颈，再选择加资源或并行并更新风险登记册 | 赶工不是越多人越快 |
| `17-04` 成本超支与挣值案例模板 | 历年下午成本题要求计算和成本控制工作 | CPI<1 且 SPI<1 时，明确成本超支、进度落后，再给纠偏措施 | 成本超支不一定进度落后 |
| `17-05` 质量问题类案例模板 | 总结经典和历年题多次考质量案例 | 张工让李工全权负责需求阶段质量控制，暴露资源冲突、授权随意和角色不清 | 项目经理不能把质量控制全权甩给 SQA |
| `17-06` 采购合同争议、索赔与收尾案例模板 | 2019 下午合同案例考分包、补充协议、索赔流程 | 建设方初验提出旧需求变更，承建方应拿出变更记录、影响分析和确认材料 | 补充协议也是合同约束 |
| `18-01` 项目章程 vs 项目管理计划 | 真题常用文件内容和发布主体设陷阱 | 任命项目经理并说明授权级别是章程；各子计划汇总是项目管理计划 | 项目经理不能自批章程 |

| `18-03` 确认范围 vs 控制质量 | 历年题直接考范围确认正确描述 | 测试通过是核实成果，客户签字才是验收成果 | 确认范围不是质量控制 |
