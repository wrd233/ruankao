# 05-05 创建 WBS、WBS 字典与范围基准

## 1. 专题定位
本专题解决“创建 WBS、WBS 字典与范围基准”在系统集成项目管理工程师考试中的识别、辨析和应用问题。它所属知识域为 **项目范围管理**，主要用途是：流程卡 / 对比卡 / 案例卡。学习目标不是背一个孤立名词，而是能在题干或案例背景中判断对象、阶段、角色、输出和错误说法。

## 2. 核心概念与边界
| 层次 | 要点 | 学习抓手 |
|---|---|---|
| 1 | WBS 是以可交付成果为导向的层级分解 | 追问“对象、条件、输出、角色、例外”。 |
| 2 | 工作包是最低层可管理单元，不等于功能模块 | 追问“对象、条件、输出、角色、例外”。 |
| 3 | WBS 字典为组件提供描述、责任、验收标准、资源和里程碑等信息 | 追问“对象、条件、输出、角色、例外”。 |
| 4 | 范围基准包括批准的范围说明书、WBS 和 WBS 字典 | 追问“对象、条件、输出、角色、例外”。 |
| 5 | 树形 WBS 直观，列表 WBS 适合大型项目和软件管理 | 追问“对象、条件、输出、角色、例外”。 |

边界提醒：本专题只处理与“创建 WBS、WBS 字典与范围基准”直接相关的概念、流程、计算或案例证据；当它与相邻专题交叉时，优先用题干中的**对象**、**过程阶段**、**责任角色**和**输出物**定位。

## 3. 知识结构
- WBS 是以可交付成果为导向的层级分解
- 工作包是最低层可管理单元，不等于功能模块
- WBS 字典为组件提供描述、责任、验收标准、资源和里程碑等信息
- 范围基准包括批准的范围说明书、WBS 和 WBS 字典
- 树形 WBS 直观，列表 WBS 适合大型项目和软件管理

建议把本专题整理成“定义、适用条件、典型输出、错误说法、真题关键词”五列。软考题经常不是直接问定义，而是把一个正确概念换到错误场景里，或者把相邻过程的输出物调换。

## 4. 关键流程 / 方法 / 公式
- 步骤是识别可交付成果、组织结构、分解、编码、检查必要且充分
- WBS 完成后还要定义活动、排序和估算

若本专题含公式，制卡时必须同时记变量含义、代入顺序和结果解释；若本专题含流程，优先拆成“谁提出、谁评估、谁批准、更新什么文件、如何验证”的小卡。

## 5. 易混点与辨析
- WBS vs 活动清单
- WBS vs OBS/RAM
- 工作包 vs 功能模块

辨析题不要靠关键词联想直接选答案，要先确认题干问的是“管理办法、工作成果、检查活动、正式验收、风险预判、已发生问题”中的哪一类。

## 6. 真题考法
- 常考 WBS 最底层不是功能模块、范围基准组成

常见命题方式包括：定义识别、过程归属、输入输出、角色权限、公式变量、案例证据归因和错误选项排除。遇到含糊表述时，优先回到教程过程定义和已批准文件。

## 7. 典型例题或题型拆解
把大型列表 WBS 改成树形，要说明树形直观但大型项目不易修改和装订

拆题步骤：先圈角色和阶段，再圈文件或数字，最后判断是否存在越权、漏评审、未确认、未走变更、公式口径错误或把相邻概念调换的问题。

## 8. 制卡建议
- 流程卡：把步骤拆成前后相邻关系和关键审批点。
- 对比卡：围绕对象、阶段、输出、角色和常见错项做双面对照。
- 案例卡：用一条背景证据反问对应管理问题、原因和措施。
- 错因卡：把真题错项改写成“为什么这句话不成立”。

Anki 卡片应保留最小上下文，例如“范围基准已批准后”“客户正式签字时”“题干给出 PV/EV/AC 时”。这样复习时训练的是迁移判断，而不是孤立背词。
