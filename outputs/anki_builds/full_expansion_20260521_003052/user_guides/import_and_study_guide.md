# 软考 Anki 导入与学习指南

## 概述

本文档面向 full_expansion_20260521_003052 构建版本，说明如何将 1,337 张 keep 卡片导入 Anki、建立正确的卡组结构、以及按不同学习阶段高效使用这些卡片。

> **本构建版本不包括 needs_human_review 卡片**，它们被单独隔离，不会混入主复习流程。

---

## 1. 导入前准备

### 1.1 获取导入文件

全量 build 完成后，导入文件位于：

```
outputs/anki_builds/full_expansion_20260521_003052/aggregate/import_preview_keep_only.csv
```

此文件包含所有通过人工审核标记为 `keep` 的卡片（约 1,337 张），按以下顺序排列：
- 章节概念卡（Chapter Concept）
- 专题问答卡（Topic QA）
- 计算专题卡（Calculation）
- 真题刷题卡（Question）

### 1.2 导入前检查

**不要** 将以下文件导入主复习卡组：

| 文件 | 内容 | 处理方式 |
|------|------|----------|
| `import_preview_keep_only.csv` | 已审核的 keep 卡片 | **导入到主卡组** |
| `all_needs_human_review_cards.csv` | 需要人工审核的卡片 | **创建一个独立的"待核验"子卡组**，单独导入，不与主复习混合 |
| `reject_candidates.csv` | 被标记为 reject 的卡片 | **不要导入**，仅作参考 |

### 1.3 人工抽检

正式导入前，建议抽检 20-30 张卡片，覆盖：
- 章节概念卡：每个章节挑 1-2 张
- 专题问答卡：S 级和 B 级专题各挑 1-2 张
- 计算专题卡：每个计算专题挑 1 张
- 真题刷题卡：上午选择题和下午案例各挑 2-3 张

参见 `review/manual_self_review.md` 获取推荐的抽检列表。

## 2. CSV 导入步骤（Anki Desktop）

### 2.1 创建卡组结构

在 Anki 中创建以下物理卡组树形结构（对应 deck_architecture.md）：

```
软考::系统集成项目管理工程师::01_信息化与信息系统::章节概念卡
软考::系统集成项目管理工程师::01_信息化与信息系统::专题问答卡
软考::系统集成项目管理工程师::02_项目管理基础::章节概念卡
软考::系统集成项目管理工程师::02_项目管理基础::专题问答卡
...
软考::系统集成项目管理工程师::计算专题卡
软考::系统集成项目管理工程师::真题刷题卡::上午选择题
软考::系统集成项目管理工程师::真题刷题卡::下午案例题
软考::系统集成项目管理工程师::待核验与复查
```

创建方法：在 Anki 中右键点击父卡组 -> "添加卡组"，输入完整路径（Anki 会自动创建层级）。

### 2.2 配置 CSV 导入

1. 打开 Anki Desktop，点击 **文件 -> 导入**
2. 选择 `import_preview_keep_only.csv`
3. 设置导入参数：

| 设置项 | 推荐值 |
|--------|--------|
| 卡组 | 选择 `软考::系统集成项目管理工程师`（后续通过改动卡组字段来分发） |
| 笔记类型 | 基础型（Basic）或自定义的"软考卡片"笔记类型 |
| 字段分隔符 | Tab（如果 CSV 是 TSV 格式）或逗号（标准 CSV） |
| 字段匹配 | Front, Back, Extra, Source, Tags |
| 允许重复 | **否**（避免重复导入同一张卡片） |
| 更新已有笔记 | 如果之前已导入旧版 build |

### 2.3 通过标签分配到正确卡组

导入后使用 Anki 的 **浏览（Browse）** 功能，通过以下标签筛选后**改动卡组**：

```
# 章节概念卡 → 分配对应章节的章节概念子卡组
tag:ruankao::family::chapter_concept

# 专题问答卡 → 分配对应专题所在的专题问答子卡组
tag:ruankao::family::topic_qa

# 计算专题卡 → 分配计算专题卡组
tag:ruankao::family::calculation

# 真题刷题卡 → 分配真题刷题子卡组
tag:ruankao::family::question
```

**操作步骤：**
1. 选中所有刚导入的卡片（浏览窗口中按导入日期排序）
2. 按 `tag:ruankao::family::chapter_concept` 筛选
3. Ctrl+A 全选 → 右键 → "改动卡组" → 选择对应章节的子卡组
4. 重复此步骤对专题问答卡、计算卡、真题卡进行分发

> 更简便的方法：使用 Anki 的 **卡组覆盖（Deck Override）** 字段直接指定目标卡组。如果 CSV 中包含 Deck 字段，导入时会自动分配到正确的子卡组。

## 3. 推荐卡组结构与用途

| 卡组 | 内容 | 学习用途 |
|------|------|----------|
| **章节概念卡** | 按章节组织的术语、定义、流程骨架 | 新章节学习、查漏补缺、考前快速扫盲 |
| **专题问答卡** | 按专题组织的辨析、场景判断、案例 | 考试反应训练、易混点突破、专题攻破 |
| **计算专题卡** | 7 个计算专题的公式卡 + 计算卡 + 陷阱卡 | 计算能力专项突破，需集中练习 |
| **真题刷题卡** | 历年真题（上午选择 + 下午案例） | 临考模拟、检验水平、熟悉出题风格 |
| **待核验与复查** | 需要人工审核的卡片 | 单独审核，审完后移入对应卡组 |

## 4. 导入顺序建议

按以下优先级分批导入，不要一次导入全部 1,337 张：

| 批次 | 导入内容 | 卡片数 | 说明 |
|------|----------|--------|------|
| **第 1 批** | 章节概念卡（01-03 章） | ~70 张 | 初次学习，先导入前 3 章 |
| **第 2 批** | 专题问答卡（信息化+PM基础+立项） | ~40 张 | 与章节同步学习 |
| **第 3 批** | 章节概念卡（04-11 章） | ~140 张 | 核心 PM 知识域 |
| **第 4 批** | 专题问答卡（核心 PM 专题） | ~350 张 | 与章节同步 |
| **第 5 批** | 章节概念卡（12-13 章） | ~34 张 | 支持知识域 |
| **第 6 批** | 专题问答卡（IT/法律/配置） | ~120 张 | 支持专题 |
| **第 7 批** | 计算专题卡（全部） | ~128 张 | 集中练习 |
| **第 8 批** | 真题刷题卡 | ~212 张 | 考前 2-3 个月导入 |

## 5. 如何筛选和分类学习

### 5.1 按章节筛选（概念卡）

```
tag:ruankao::chapter::01
tag:ruankao::chapter::03
tag:ruankao::chapter::05
```

适用于：正在学习对应教材章节时，只复习该章概念。

### 5.2 按专题筛选（问答卡）

```
tag:ruankao::topic::T-COST-002
tag:ruankao::topic::T-SCH-003
tag:ruankao::topic::T-RISK-002
```

适用于：专项突破某个知识领域。

### 5.3 按计算专题筛选

```
tag:ruankao::family::calculation tag:ruankao::topic::T-SCH-003
tag:ruankao::family::calculation tag:ruankao::topic::T-COST-002
```

适用于：专门练习某个计算类型。

### 5.4 按考试年份和题型筛选（真题卡）

```
tag:ruankao::year::2019 tag:ruankao::question_type::morning_choice
tag:ruankao::year::2010 tag:ruankao::question_type::case_question
```

适用于：模拟某一年份的考试。

### 5.5 按重要性筛选

```
tag:ruankao::importance::A
```

适用于：考前冲刺，只看高频 A 级卡片。

### 5.6 按家族类型筛选

```
# 只看概念辨析卡
tag:ruankao::card_type::discrimination

# 只看流程卡
tag:ruankao::card_type::process

# 只看计算卡
tag:ruankao::card_type::calculation

# 只看案例卡
tag:ruankao::card_type::case
```

## 6. 卡片类型与学习技巧

### 6.1 概念卡（章节目录下）

| 特征 | 学习技巧 |
|------|----------|
| Front 是术语名称，Back 是定义 | 先闭眼回忆定义，再看背面验证 |
| Extra 包含易错点和关联 | 易错点部分单独读一遍，理解为什么容易错 |
| Source 标记来源 | 有疑问时回查教材对应章节 |

**技巧：** 概念卡适合在学完新章节后立即刷。不要试图一次记住所有概念——利用 FSRS 间隔重复自然巩固。

### 6.2 辨析卡（专题问答）

| 特征 | 学习技巧 |
|------|----------|
| Front 是一组混淆项或场景描述 | 在脑中列出区别点，再对照 Back 验证 |
| Extra 包含深层理解和记忆线索 | 利用记忆线索（口诀、首字母法）辅助记忆 |
| 关联字段指向其他相关卡片 | 做完一张后点关联卡继续做，形成知识链 |

**技巧：** 辨析卡是考试提分的核心——大部分选择题考的就是"区分相似概念"。建议在概念卡刷过一轮后集中攻克。

### 6.3 计算卡（计算专题）

| 特征 | 学习技巧 |
|------|----------|
| 公式卡：公式 + 变量解释 | 先理解每个变量的含义，不要死记公式 |
| 计算卡：题目 + 解答过程 | 在草稿纸上完整计算一遍，再对照答案 |
| 陷阱卡：常见错误变体 | 重点关注：单位错误、公式套错、符号混淆 |

**技巧：** 计算卡需要"动手算"而不是"用眼看"。建议在草稿纸上完整写出计算步骤。每个计算专题先做 3-5 道基础计算，再做陷阱卡。

### 6.4 案例卡（真题+案例专题）

| 特征 | 学习技巧 |
|------|----------|
| 题干摘要：重现案例场景 | 草拟答题框架——问题识别、原因分析、解决措施 |
| 答案框架：得分要点 | 对比自己的框架，找出遗漏点 |
| Extra：易漏点和答题技巧 | 重点关注：漏掉了什么？为什么漏了？ |

**技巧：** 案例卡不要追求"一次背完"——先建立框架思维（看到问题→立即联想到对应知识域和过程），再填充细节。每道案例尝试口头复述答题要点。

## 7. 学习调度建议

### 7.1 新卡片/天设置

| 备考阶段 | 新卡/天 | 说明 |
|----------|---------|------|
| 初期（1-2 个月） | 15-20 张 | 以概念卡为主，建立知识骨架 |
| 中期（3-4 个月） | 25-35 张 | 增加专题问答卡和计算卡 |
| 冲刺（考前 1 个月） | 0-10 张 | 减少新卡，重点复习已有卡片和真题 |

### 7.2 复习上限

| 阶段 | 复习上限/天 | 说明 |
|------|------------|------|
| 工作日 | 150-200 张 | 利用通勤、午休、晚间时段 |
| 周末 | 300-400 张 | 集中攻克计算和专题 |
| 冲刺期 | 200-300 张 | 保持高频接触，但不过载 |

### 7.3 FSRS 参数建议

Anki 23.10+ 支持 FSRS 算法。推荐参数：

- FSRS 启用：**是**（远优于传统 SM-2 算法）
- 保留率目标：**0.90**（软考需要较高的精确回忆率）
- 最大间隔：**180 天**（软考备考周期通常 3-6 个月）

> 不需要手动调优 FSRS 参数 — Anki 的 FSRS 优化器会根据你的历史表现自动校准。

## 8. 待核验卡片处理

### 8.1 识别待核验卡片

待核验卡片通过以下标签标识：

```
tag:ruankao::needs_review
tag:ruankao::not_for_main_review
```

### 8.2 处理方法

1. **单独导入**：创建一个名为 `软考::系统集成项目管理工程师::待核验与复查` 的独立子卡组
2. **将待核验卡片导入到此卡组**，不要混入任何主复习卡组
3. **逐张审查**：
   - 如果卡片内容正确 → 移除 `needs_review` 标签，移入对应学习卡组
   - 如果卡片内容有误 → 修正后移入对应学习卡组
   - 如果卡片无法修正 → 删除或保留在待核验卡组中

### 8.3 关键警告

> **永远不要将 `needs_human_review` 卡片导入主复习卡组。**
>
> 这些卡片包含未经审核的内容（如 OCR 错误、格式问题、歧义表述），直接混入主复习会导致记忆错误知识的风险。

## 9. 常见问题

### Q: 我应该一次导入所有卡片吗？

**不建议。** 分 4-6 批导入，与你的学习进度同步。详见第 4 节"导入顺序建议"。

### Q: 章节概念卡和专题问答卡内容重复了怎么办？

这是"双轨制"设计的有意冗余——概念卡负责"是什么"，问答卡负责"怎么考"。两者可以合理重复，但复习时分开进行。不必试图去重。

### Q: 计算卡需要单独一个卡组吗？

是的。计算卡需要"动手算"的学习方式，与概念卡/问答卡的"记忆"方式不同，单独一个卡组可以集中练习。

### Q: 如何利用标签创建过滤卡组（Filtered Deck）？

参见 `filtered_deck_suggestions.md` 获取 8 种不同学习场景的过滤卡组配置。

### Q: 有推荐的学习路线吗？

参见 `study_route.md` 获取从基础到冲刺的 6 阶段渐进式学习路线。

## 10. 反馈闭环

如果一张卡连续多次遗忘（在 FSRS 中显示高难度），**不要硬背**。采取以下措施：

1. 拆分：将一张大卡拆成多张小卡（如"整体变更控制的 6 个步骤"拆成 6 张单步卡）
2. 改写：调整 Front 的措辞，使其更贴近考试实际出题方式
3. 加例子：在 Extra 字段补充具体的考试真题或场景例子
4. 标记：在卡片上添加 `flag:review_again` 标签，提醒在下一个复习周期中重点关注

> 坏卡（Bad Card）无法靠 FSRS 参数调优解决——需要重新设计卡片而不是调整算法。
